- **1 ファイルは 2,000 行を目安**にする。超えたら責務で割る。
- コメントとログの文体は既存に合わせる (コメントは日本語、ログ文字列は英語)。
- **作業で `$HOME` に書かない** (2026-09-26、利用者の決定。**例外は rustup / cargo の `~/.rustup` と `~/.cargo`** — ほかの作業でも使うので許す)。雪像は `status/`、一時ファイルはスクラッチパッドか `/tmp`、手元で起動するプロキシは
  `HOME` をスクラッチに向ける (プロキシは `$HOME/.rust-http-proxy.*` に状態を書くため)。**作業に要る自作の道具は `scripts/` に入れてコミットする** (`scripts/mx` など)。
- **権限を上げる手段 (`sudo`・`sysctl` で締め付けを緩める等) は、よほどのものでなければ使わない** (同日、利用者の決定)。`unshare` の要る
  `scripts/deployed-like.sh` は CI (`deployed-like-snapshot`) で回す。

**作業の進め方 (毎タスク共通)**:

1. 着手前に対象ファイルを読み、README の該当箇所を確認する。**着手前に「今どうなっているか」を測る。**
2. 実装 → `cargo fmt` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace --no-fail-fast` (CI と同じ。1 本落ちても残りを走らせる) → `cargo build --release`。
3. 性能に関わるタスクは **変更前後の計測値** を取り、コミットメッセージ本文に貼る (`docs/measuring.md`)。
4. 環境変数や挙動を足したら README の表と説明を更新する。
5. コミットメッセージは既存に合わせて `feat:` / `fix:` / `perf:` / `docs:` / `chore:` / `refactor:` / `test:` の接頭辞。
6. 判断に迷ったら「速い方・単純な方・既定で安全な方」を選び、理由をコメントに残す。
7. 終わったら台帳 (`TASKS.md`) の該当タスクを `[x]` にし、`結果:` に実測値とコミットを書く。`docs/status.md` の表に効く数字が変わったら更新する。
8. 実装を Opus (サブエージェント) に渡すときは `docs/handoff.md` の「実装を Opus に渡すときの決まり」を指示文に貼る。
9. **再デプロイの直前と直後に `scripts/collect-deployed.sh` を 1 枚ずつ撮る** (直前 = 判定の「前」、直後 = 0 時間の雪像)。利用者が再起動したら親が撮り、そのタスクの `Tn.99` の前提に**版 (`/status` の `version`) と起動時刻 (UTC)** を書く (T17.19。T16 の再デプロイは記録が無く、2026-09-26 に `uptime_secs` から起こした)。README の「運用」の「置く前 (`--check`)」と「起動直後 (0〜5 分)」も同じ内容。
   **クラウドのセッションから締めるとき** (T27.2。T25.99 がそうだった): (a) エージェントのプロキシは平文の HTTP を通さず CONNECT だけを通すので、`VIA=$HTTPS_PROXY scripts/collect-deployed.sh …` で回す (デプロイ先への curl が全部 `-x "$VIA" -p` になる。`PROBE` は既定で 0、`probe-deployed.sh` は `VIA` があると測らない)。環境のネットワークの許可にデプロイ先のホストが要る。(b) 手元の「前」と「0 時間」の雪像はコンテナに無い (`status/` は gitignore)。**「前」は `--from-server` で取り寄せたサーバーの日次のうち、再デプロイより前でいちばん新しい 1 枚** (`<日付>T000000Z-snapshot.json`。日付の翌日 00:00 UTC に撮ったもの) を `BEFORE` にし、結果にそう書く。日次の `/recent` は 1 時間ぶんしか無いことがあり、phase25 はそのとき接続のエラーの行を「判定できず」にする (T27.0)。0 時間の雪像は、`memory.baseline` がある版 (0.24 以降) なら phase24・phase25 では要らない。(c) コンテナは回収されると消えるので、撮った雪像は締めの結果に名前と要点を書いて残す (中身はコミットしない)。
