# docs/handoff.md — タスクの渡し方

## タスクの形式

> T37.5 で `TODO.md` の冒頭から移した。

**タスクの形式**: 済んだ作業もこれからの作業も、同じ 1 つの形で書く (未着手は [`TASKS.md`](../TASKS.md)、済んだタスクは `tasks/TNN.md`)。

```
- [x] **Tn.n 題**
  - 目的: なぜやるか
  - 変更箇所: どのファイル (済んだものは、いまコードがある場所)
  - やること: 何をするか
  - 受け入れ基準: どうなったら終わりか
  - 結果: 実測値と結論 (`コミット`)   ← 終わったものだけ
```

1 タスク = 1 コミット。性能に関わるものは **変更前後を必ず測って** コミットメッセージ本文に貼る。
測って「やらない」と決めたものは消さずに `docs/rejected.md` に残す (同じ道を二度調べないため)。
番号は付けた順で、並び替えても振り直さない (コミットメッセージから引けるように)。**各タスクの `Tn.99` は「デプロイ後の様子見と修正、
締めの文書」に予約する** (タスク 14 から。デプロイして数字を見てから書くタスクを、そのタスクの最後に置くため。`.9` ではなく `.99` なのは、
タスクが 9 つを超えても番号がぶつからないように)。**`Tn.99` の最後の手順は「次のターンの準備」** (2026-09-24、利用者の決定): 判定のあと、
(1) 次の再デプロイで何を判定するか (次のタスクの完了の定義の下書きと、今回「判定できず」になった項目) を並べ、(2) それぞれに要る計器がデプロイ先で**いま**出ているかを
雪像で確かめ、(3) 足りない計器は `T(n+1).0` として**次の再デプロイの前に**入れる (タスク 15 の T15.0 と同じ「計器が先」)。(4) 利用者に再デプロイを頼むのは、足りない計器を入れ終えてから。
計器の無いまま出すと、その 24 時間は判定に使えない (2026-09-24 の T15.99 は、再デプロイを頼んだあとで計器の不足に気づいた)。

## タスク 15 の渡し方 (2026-09-18 版。指示文の型)

**タスク 15 の渡し方 (2026-09-18 版。下の「実装を Opus に渡すときの決まり」より新しく、食い違う所はこちらが正)**:
タスク 14 で固まった運用を 1 つの型にした。親は下の型を指示文に貼り、`<…>` を埋める。**1 単位 (または 1 タスク) = 1 エージェント = 1 worktree**。

1. **作業場所**: 最初に worktree を自分で作る — `git -C /home/takano32/GitHub/rust-http-proxy worktree add -b <波の名前>/<id> /home/takano32/GitHub/rust-http-proxy-wt/<id> main`
   (波の名前は親が指示文に書く。T15.0 の波は `wave8`、T15.4 / T15.6 は `wave9`)。
   以後はそこだけで作業し、main のチェックアウトは触らない。`git push` はしない。**`TODO.md` は編集しない** (`結果:` の文面は最後の報告に書き、親が貼る)。
   デプロイ先 (`nagoya.sorahost.net`)、`~/rust-http-proxy-status/`、本物の `~/.rust-http-proxy.*` には触らない。
2. **最初に読むもの**: `docs/goals.md`、`docs/measuring.md` の「速さの測り方」、この「渡し方」、T15.0 の「決まり」と「欄の名前」、自分の単位の本文。
   本文が挙げるソースは**関数の全体と呼び出し元**まで読む。**本文の行番号は書いた時点の main のもの** (T15.0 の本文は `71d1d0b`、T15.4 / T15.6 / T15.99 は T15.0 のあとの `5f6523b` で確かめ直した。T15.12 は着手の前にもう 1 回確かめる) なので、ずれていたら近くを
   `grep` して確かめてから触る。本文と違う事実を見つけたら、直す前に「どこがどう違うか」を控えて報告に書く。
3. **確かめ**: `cargo fmt --all` → 触ったクレートだけ `cargo clippy -p <crate> --all-targets -- -D warnings` (結合テストを足したら
   `-p rust-http-proxy --all-targets` も) → **自分が書いたテストと、本文が名指しした既存のテストだけ**を名前で回す
   (`cargo test -p <crate> <名前>` / `cargo test --test <ファイル名>`)。**`cargo test --workspace` は回さない** (全体テストは波の最後に親が 1 回)。
   cargo とベンチは**必ず `scripts/mx` 経由** (2026-09-26 まで `~/.local/bin/mx` にしか無かったのをリポジトリに入れた) (機械のロック。`mx cargo test --test foo`)。A/B の一式は 1 回の `mx bash -c '…'` の中で。
   `.cargo/config.toml` の `jobs = 1` はそのまま。
4. **プロセス**: 手でプロキシを起動するときは `timeout 120`、`HOME` **と `XDG_CACHE_HOME` (か `PROXY_CACHE_DIR`)** は一時ディレクトリ (既定プロファイルの
   ディスクキャッシュは `HOME` を見ないので、`HOME` だけだと本物の `~/.cache/rust-http-proxy` を開く)、curl は `-m 5`、プロキシを自分宛てにしない。
   **止めるのは自分が起動した PID だけ** (`pkill -x rust-http-proxy` は使わない)。終わったら自分のプロセスを残さない。作業ファイルはスクラッチパッドに
   `<id>-` で始まる名前で置く。
5. **守ること**: 外部クレートは足さない。システムコールは `crates/sys/src/sys.rs` と同じ `unsafe extern "C"` + `#[cfg(target_os = "linux")]` (他 OS は従来の動き)。
   認証は入れない。**接続元・宛先・ポートの制限を既定で入れない** (利用者の決定 2026-09-18)。要求の経路は増やさない (本文が「例外」と書いた所だけ)。
   JSON は足すだけ (`"schema":1` のまま、欄を消さない・意味を変えない・既存の鍵の順を変えない)。コメントは日本語、ログの文字列は英語。
6. **性能に関わるとき** (本文が「測る」と書いた単位だけ): 変更前のバイナリを `rust-http-proxy` という名前のまま別ディレクトリに退避し、
   `scripts/cpu-per-request.sh` を前後交互に 3 組 (`--only connect` は **6 組**)・各 10 秒、ビルド直後は捨て走り 1 本、中央値で比べる。
   差が ±4% の中なら「ぶれの中」と書く。
7. **コミット**: 既存の形式 (`feat:` / `fix:` / `test:` / `docs:` / `refactor:` + 日本語 1 行 + 本文)。1 項目 1 コミットが基本。末尾に
   `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`。手放す前に `git merge main` を 1 回 (親が `TODO.md` を動かしている)。
8. **できなかったとき**: 再現や計測が本文のとおりにならなかったら、**別の直しを自分で考えて入れない**。試したことと起きたことをそのまま報告して終わる。
9. **最後の報告に入れるもの**: コミットの hash・worktree と枝、前後の表 (測った単位)、回したテストの名前と本数、やり残しと気づいた問題、
   `TODO.md` に貼る `結果 (<日付>、<hash>): …` の 1 段落。**T15.0 の単位はこれに加えて「後ろの単位のために残すもの」**:
   (a) 足した欄の名前・型・単位・「通算か区間か」の表、(b) その欄を含む**作り物の JSON の例**を 1 つ (値は架空。本物の雪像から写さない)、
   (c) README の該当する口の説明に自分で足した行 (`scripts/check-docs.sh` は欄の説明を見ないので、足し忘れは誰にも見つからない)。
   **README の説明に自分で足す行は T15.0 以外のタスクにも要る** (`check-docs.sh` は README の説明文も既定値も見ない)。README の環境変数の表は**自分の行だけ**触る (並列のマージの衝突を避ける)。

**親がすること** (マージごと): `git merge --no-ff` → **触ったクレートごとに** `cargo check -p <crate> --all-targets` (ワークスペース全体の check は
テストの中の壊れを 1 回見逃した) → `python3 -m unittest discover -s scripts`、`node scripts/check-dashboard.js`、`./scripts/check-docs.sh` →
`結果:` を貼って `[x]` → 走っているエージェントに main が動いたことを知らせる → worktree を消す (枝は残す)。
**波の最後に 1 回だけ**: `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、
`cargo test --workspace --no-fail-fast` (落ちた binary だけ 5 回繰り返して flake を切り分ける)、`cargo build --release`、
`scripts/build-memory.sh 180`、`--lite` のシステムコール数と確保数、`--only connect` の CPU/本。

## 実装を Opus に渡すときの決まり

**2026-09-18 の注**: タスク 14 で固まった運用 (worktree を自分で作る / lint と自分のテストだけ / 全体テストは波の最後に 1 回 /
`mx` 経由 / `TODO.md` は親だけ / 自分の PID だけ止める) は **タスク 15 の「渡し方」にまとめた**。下の「渡し方」の「直列に回す」と
「エージェントが守ること」のうちタスクごとに全部通す項は古く、食い違う所はタスク 15 の方が正。外部クレートを足さない項・性能の測り方の項・効かなかったら戻す項・コミットメッセージの項・最後の報告の項は今も生きている。

ここから下のタスクは、1 つずつ Opus (Claude Code のサブエージェント) に渡して実装する前提で書いてある。
渡すときの指示はこの節と各タスクの本文だけで足りるようにしてある (別のメモは要らない)。

**渡し方**: 1 タスク = 1 エージェント = 1 コミット。直列に回す (ベンチが重なると計測が汚れる。`TODO.md` の取り合いにもなる)。
指示文には「最初に読むもの」として `docs/goals.md`・`docs/measuring.md`・`docs/rejected.md` とそのタスクの本文、触るクレートのソース全体を挙げ、
下の「エージェントが守ること」を貼る。おすすめの順は **T9.3 → T9.4 → T8.1 → T9.5 → T8.5 → T8.6**
(効きの大きさと、後のタスクが前の結果を使う順。T9.4 は T9.3 の `SO_RCVTIMEO` を、T8.5 は T8.1 の結果を使う)。

**エージェントが守ること** (指示文にそのまま貼る):

1. 外部クレートは 1 つも足さない。システムコールは `crates/sys/src/sys.rs` と同じ `unsafe extern "C"` + `#[cfg(target_os = "linux")]`、
   他 OS には従来コードを残す。認証は入れない。既存機能を壊さない。
2. `cargo fmt` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace` → `cargo build --release` を通してからコミット。
   `.cargo/config.toml` の `jobs = 1` はそのまま。
3. 性能に関わる変更は、**変更前のバイナリを退避して、変更後と交互に 3 回ずつ 10 秒** (`scripts/cpu-per-request.sh`、`BIN=` で切り替え) 測り、
   **ビルドとベンチの間には捨て走りを 1 本入れる** (T10.11。ビルド直後の 1〜2 本は 15〜20% 重く出る)。
   中央値で比べる。差が 5% 未満なら「ぶれの中」と正直に書く。システムコールは strace の下でプロキシを起動して数える (`docs/measuring.md`)。
   計測中は他のビルド・ベンチを走らせない。終わったらプロキシとベンチのプロセスを残さない (`pgrep -x rust-http-proxy` が空)。
   **A/B 用に退避するバイナリは `rust-http-proxy` という名前のまま別ディレクトリに置くこと** (T11.1)。
   `mx` の待ちループも `strace` の停止も `pgrep -x rust-http-proxy` を使うので、名前を変えると
   止められずにロックを占有し続ける (実際に 20 分止まった)。
4. 効かなかったら**戻す**。戻した案は `docs/rejected.md` の表に数字つきで 1 行足す (これも 1 コミット)。
5. コミットメッセージは既存の形式 (`perf:` / `feat:` / `fix:` / `docs:` / `chore:` / `refactor:` / `test:` + 日本語 1 行 + 本文に前後の表)。
   `Co-Authored-By:` にモデル名を付ける。**`git push` はしない** (main にもブランチにも。CI で確かめたいときは人が push する)。
6. 終わったらそのタスクを `[x]` にして `結果:` に実測値とコミットを書く。`docs/status.md` の表に効く数字が変わったら更新する。
   環境変数や挙動を足したら README の表と説明も更新する。
7. 最後の報告に、コミットハッシュ・前後の表・テストの本数・やり残しと気づいた問題を入れる。

**この機械で分かっている計測の癖** (エージェントに伝える): `strace -p` は `ptrace` が拒まれる (strace の下で起動する)。
`perf` は `perf_event_paranoid = 2` でユーザー空間しか数えず、既定の `cycles` はサンプルがほぼ取れないので `-e cpu-clock` を使う。
CPU/要求 は 5 秒の計測で ±8% ぶれる。ビルドの通る最小メモリは境目が 1 MB 刻みで薄いので、機械を占有して測る (T10.9)。手元 99 MB / CI 100 MB でほぼ同じ (T11.7)。

**済んだタスクの本文はすべて [`tasks/`](../tasks/README.md) にある** (タスク 0〜14 は 2026-09-26 に `docs/HISTORY.md` へ、2026-10-22 にタスクごとに `tasks/TN.md` へ分けた。タスク 15 以降は 2026-10-22 に移した)。コメントの `TODO.md Tn` は `tasks/TNN.md` で引ける (番号はそのまま)。
