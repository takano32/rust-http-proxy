# S20 日次の要約と SLO (`/daily`・`/slo`)

1 日 1 行の要約を永久に残す規則と、SLO の閾の達成率の出し方。

経緯と測った数字は [`specs/HISTORY.md`](HISTORY.md) の「S20 日次の要約と SLO (`/daily`・`/slo`)」。

### `/daily`

- **日次の要約 (永久に残る。T14.20)**: `/daily?n=365` (既定 1 年、最大 4,096 日) は
  `$HOME/.rust-http-proxy.daily.jsonl` の中身を**古い順**にそのまま返す。`/history` は 30 日で消えるが、
  こちらは**「いつから遅くなったか」「デプロイの前後で何が変わったか」を年単位で**追うためのもので、
  1 日 1 行 (ありふれた 1 行 460 B、上限 672 B。T32.17・T32.18) なので 1 年で約 170 KB
- 1 行 = `day` (UTC の日付) ・`t` (その日の 0 時の epoch 秒)・`secs` と `samples` (**その日をどれだけ見ていたか**。
  **再起動した日も前のプロセスのぶんが入る** — 起動して最初の標本で、`.rrd` から読み戻した `history["60"]` の UTC 0 時からの
  行で今日の積み上げを組み直す (T32.18)。前のプロセスの最後の 1 分と山の写真の枚数は戻らない。`PROXY_STATS_PERSIST=off` と `.rrd` の無い起動は
  いまのプロセスのぶんだけ)・`requests`・`bytes`・`connects`・`connect_p50_ms` / `connect_p95_ms`・
  `dns_misses` / `dns_per_connect` / `dns_miss_ms`・`errors`・`bursts` (山の写真の枚数)・`active_max`・
  `evicted_idle`・`rss_max` / `rss_avg`・`version` (その日動いていたバイナリの版。**組み直した日は `/events` の `start` から「その日に動いた版」を古い順に空白で
  並べる** (`0.29.36+10cff6e 0.30.3+7f86d30` のように。80 文字まで、越えたら古い方から落とす。T32.18))・
  **`slo_rate_hours`** (T29.33。`/slo` の比の 2 つを 1 時間の合計で判定した `{"error_rate":[満たした時間, 外した時間],
  "dns_miss_per_connect":[…]}`。`/slo` の集計はメモリだけなので、その日のうちこのプロセスが動いていた時間だけ)・
  **`dns_fail_misses` / `dns_resolved_per_connect`** (T32.17。`dns_misses` のうち名前解決に失敗した試みのぶんと、それを除いた
  `(dns_misses − dns_fail_misses) ÷ connects` = `/slo` の `dns_miss_per_connect` と同じ数え方。`dns_per_connect` は
  失敗も入れた値)
- 累計 (要求数・バイト・追い出し・山) は**日の境目の値の差**、区間の値 (確立時間の分布・エラー・名前解決) は
  **その日の標本の足し合わせ**、ゲージ (同時接続数・RSS) は**最大と平均**
- **書くのは履歴スレッドが UTC の日付をまたいだ瞬間の 1 回だけ** (要求の経路の費用は 0)。
  ファイルは**追記のみ**で上限 **2 MiB** (越えたら古い行から捨てる = 約 11 年ぶん)、
  起動時に最後の行の日付を見るので**同じ日に 2 回起動しても 1 行のまま**。
  `PROXY_STATS_PERSIST=off` では 1 行も書かない (`/daily` の `path` が `null`)。
  応答は他の個票と同じく 256 KiB 以下 (切ったら `truncated`)。
  この応答をそのまま `scripts/weekly-report.py` に渡せば、スナップショットが無くても週次の表が出る

### `/slo`

- **SLO の達成率 (T14.50)**: `/slo?days=7` (既定 7 日、最大 31 日。「今日」は **UTC**) は、
  `PROXY_SLO` の 4 つの閾を **5 秒の標本 1 本ごと**に判定した結果を、**日ごと (`daily`)・時間ごと (`hourly`)**
  の達成率と、**外れた時間帯の一覧 (`breaches`)** にして返す。
  **読み方**: `ratio` = `met ÷ judged` = **4 つとも満たした 5 秒の割合**で、`judged` は「確立か、名前が引けたうえでの 443・80 宛てのエラーが 1 本以上あった 5 秒」だけを数えます
  (T20.4・T28.45・T30.3。どちらも無い 5 秒は分母に入らないので、静かな時間帯があっても達成率は薄まりません。判定できた標本が 1 本も無ければ `ratio` は
  `null` で、**0% ではありません**)。`misses` は閾ごとに外した標本の数 (`names` と同じ並び)。
  `breaches` は**連続する外れを 1 行に畳んだもの**で、1 行 = 開始・終了 (`from` / `to` と、人が読む `from_hour` / `to_hour`)・
  続いた時間数・その間の `judged` / `met` と、**どの閾を外したか・その最悪の値** (`breached[]` の `name` / `samples` / `worst` / `threshold`)。
  例: 「99.2% の時間で満たした。外れたのは 09-11 17〜23 時 (`connect_p50_ms` 5,040 本、最悪 46.9 ms、閾 10 ms)」。
- **確立の 2 つ** (`connect_p50_ms` / `connect_p95_ms`) は**確立そのものではなく、CONNECT 1 本ごとの「確立 − オリジン側のカーネルの RTT」**
  の p50 / p95 で、既定は **5 / 50 ms** (T28.45。確立の p50 は 1 RTT = 距離で決まるため)。
  窓は `/history` の **`conn_excess_*`** (`ms.connect − rtt_ms.origin`。名前解決を含まない。T29.12) で、`/slo` の `basis` の `connect` が
  **`connect_minus_rtt`**。**名前解決の遅れは異常検知の `dns_slow` (S15) に任せ**、`/slo` に閾は持たない。
  窓が空の 5 秒 (RTT が読めない Linux 以外の環境・T29.12 より前の標本) は確立の 2 つを外さない。
  `/slo` の `basis` に読み方が出る (T28.45 より前の `/slo` には `basis` が無い)
- **`error_rate`** は**名前解決に成功した試みあたり** (T28.45。`(エラー − dns) ÷ (確立 + 転送 + エラー − dns)`。メール宛の総当たりの NXDOMAIN を数えない)。
  **宛先のポートが 443・80 の試みだけ**を数える (T30.3。利用者の決定): 分子と分母は `/history` の
  **`other_port_attempts` / `other_port_errors`** (443・80 以外の宛先への試みとそのエラー) を引いたもので、
  **443・80 以外のエラーしか無い 5 秒は「判定なし」**。443・80 以外のエラーは `/errors`・`/history` の
  `errors_by_cause`・判定表の表示だけの行で見える。T30.3 より前の標本は 2 列が 0 なので、443・80 に絞らない数え方で読める。
  例: 1 時間に `:993` の時間切れ 100 本と `:443` の成功 1,000 本・エラー 4 本なら 4 / 1,004 = 0.0040 で満たす
- **`dns_miss_per_connect`** は**名前解決に失敗した試みのミスを除いた**ミス ÷ 確立 (T28.45)。名前解決の失敗しか無い 5 秒は「判定なし」。
  確立の 2 つと `dns_miss_per_connect` は全部のポートを数える
- **比の 2 つ (`error_rate` と `dns_miss_per_connect`) は 1 時間の合計で判定する** (T29.33。利用者の決定。
  `basis` の 2 つに `_hourly_sum` が付き、`rate_window_secs` が `3600`。`error_rate` の `basis` は T30.4 の
  **`resolved_web_attempts_hourly_sum_excluding_top_destination`**)。
  **速さ (確立の 2 つ) は 5 秒の標本ごと**、比の 2 つは **UTC の 1 時間の区切りごとの分子と分母の合計**で判定し、
  **`met` = 速さの 2 つを満たし、かつその時間の比の 2 つも満たした 5 秒** (比を外した時間は、その時間の 5 秒を全部
  「達成していない」と数える。いまの時間はそこまでの合計で判定)。`misses` の 3・4 番目は比を外した時間の判定した 5 秒の数、
  `breaches[].breached[]` の比の行には外した時間の数 (`hours`) とその時間帯の合計 (`num` / `den`) が付く。
  分母は `error_rate` が「確立 + 転送 + エラー − 名前解決の失敗」、`dns_miss_per_connect` が確立の本数で、
  `today` と `daily[]` の **`rates`** に比ごとの合計 (`num` / `den` / `value`) と満たした / 外した時間の数
  (`hours_met` / `hours_missed`)、`hourly` の末尾の列 **`rate_sums`** に時間ごとの `[[分子, 分母], [分子, 分母]]`、
  **`last_hour`** に**直近 1 時間** (いまから 3,600 秒。時間の区切りをまたぐ) の合計と閾に当てた `met` が出る。
  例: 1 時間に確立 1,000 本・エラー 4 本 (4 / 1,004 = 0.0040) なら満たし、6 本 (6 / 1,006 = 0.0060) なら外す。
  エラーが確立 1 本だけの 5 秒にあっても結果は同じ
- **`error_rate` は 1 つの宛先に偏ったエラーを外す** (T30.4。利用者の決定): **その時間のエラーが 2 件以上で、いちばん多い宛先
  (ホスト別統計の鍵) がその時間のエラーの半分以上なら、その宛先の試行とエラーを分子と分母から外す** (外すのは 1 つだけ。
  エラーが 4 つの宛先に 1 件ずつ・1 件だけの時間は外さない)。外した宛先は `hourly` の末尾の列 **`excluded`**
  (`{"destination":"connect://pravda.me:443","errors":16,"attempts":16,"hour_errors":16}`、外していない時間は `null`)、
  `today` / `daily[]` の `rates.error_rate.excluded` (`hours` / `errors` / `attempts`)、`breaches[].excluded`
  (`hours` / `errors` / `attempts` / `destinations`)、`last_hour.rates.error_rate.excluded` (`errors` / `attempts` / `destinations`) に出て、
  `num` / `den` と `rate_sums` は外したあとの数。いまの時間は途中の集計で外し、`last_hour` (いまから 3,600 秒) は前の時間に
  外した宛先を窓に掛かる秒の割合で按分して引く (いまの時間のぶんはまるごと窓に入るのでそのまま)。
  宛先ごとの数は 5 秒の標本 (`.rrd`) には無く、ホスト別統計から切り離した小さな表 (その時間の 443・80 のエラーの
  宛先だけ、64 宛てまで。T32.10。ホスト別統計が満杯で `other` に畳まれた宛先も数える) と表 (いまの時間・エラーの合計・
  いちばん多い宛先) に持ち (成功の本数だけはホスト別統計の行の `web_hour` から読む)、履歴スレッドが 5 秒ごとに `/slo` に渡す。成功の本数は時間の区切りで写した `timed`
  (応答時間を測った要求の通算) と、そのうちのエラーの通算からの差で出すので、**要求の経路に足すのはエラーのときだけ**
  (区切りで全部の行を舐めるのは 1 時間に 1 回)。`/slo` の集計もメモリだけなので、**起動し直すと両方とも 0 から揃って数え直し**、
  起動した時間は起動してからの分で判定する。時間の区切りの前後 5 秒ぶんは、5 秒の標本 (標本を取った時刻の時間に入る) と
  宛先の数 (エラーの時刻の時間に入る) で 1 時間ずれることがある。
  例: 1 時間に `:443` の成功 400 本・`pravda.example:443` の時間切れ 4 件・ほかの宛先のエラー 1 件なら 1 / 401 = 0.0025 で満たす
  **使い道 (T14.99)**: タスクの完了の定義は「平常時の CONNECT 確立 p50 6 ms 以下」のような閾値ですが、
  `PROXY_SLO=connect_p50_ms=6` を入れておけば、`/slo` の `ratio` がそのまま
  **「その閾を満たしていた時間の割合」**になり、判定が「満たした / 満たさない」ではなく
  「99.2% の時間で満たした。外れたのはこの時間帯」と数字で書けます。
  集計は**メモリだけ**で 31 日ぶん (1 時間 1 行 × 744 = 約 52 KiB と、直近 1 時間の 5 秒ごとの分子・分母 約 28 KiB)、**再起動で消えます** (`first_t` / `last_t` でどこから見ているかが分かります)。
  応答は **64 KiB 以下** (越えるぶんは外れた時間帯と時間ごとの行から落として `truncated`)。
  ダッシュボードの KPI「今日の SLO」も同じ口を 30 秒に 1 回読む (`/slo` を持たない版ではカードごと出さない。
  内訳に今日の比の合計 (分子 / 分母) と 1 時間の合計で外した時間の数も出す。T29.33)
